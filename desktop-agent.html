How the Work Agent helps with tasks

Use this like a focused task board instead of a normal chat. Stellar separates thinking, repository inspection, approved implementation and verification so you can see what it is doing.

01 · AskDescribe the result

Tell Stellar what you want fixed, built, researched or tested. Keep secrets out of the prompt.

02 · InspectRead-only evidence first

Stellar checks files, folders, search results, git status and diffs before suggesting edits.

03 · ApproveYou control actions

Write, terminal and browser steps stay visible. Dangerous system paths and secrets remain blocked.

04 · VerifyReview outputs

Results, test output and diffs come back to the page so you can decide the next move.

Good for

Website fixes, UI cleanups, bug hunts, repo reviews, tests, docs and project tasks.

Needs approval

File writes, terminal commands, opening URLs and any task that changes your workspace.

Not allowed

Passwords, API keys, payment details, system folders, browser secrets or disabling security tools.

1. Connected app pairing

Pair StellarX like a connected app: create a one-time code, approve it on your own Windows companion, then this page shows Connected / PC online.

StellarX works like a plugin connection: every signed-in user pairs only their own PC and can disconnect anytime.

2. Install Windows companion

The companion runs locally; the website never receives your Windows password.

PowerShell: irm https://raw.githubusercontent.com/zitopop/Stellar-AI/main/desktop-agent/install-windows.ps1 | iex Then: cd "$env:LOCALAPPDATA\StellarAI\DesktopAgent" node agent.mjs pair YOUR_CODE .\start-stellar-agent.cmd
Terminal commands are OFF by default. Enable them only when you want reviewed shell tasks: $env:STELLAR_DESKTOP_ALLOW_SHELL="1" before starting the agent.

Safeguards

Two layers protect the PC: cloud permissions here, plus local Windows safeguards in the companion.

Hard blocks always stay on: destructive disk/system commands, security-tool disabling, credential/key stores, browser secret stores, Windows system directories, and access outside the workspace.
