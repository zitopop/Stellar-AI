Ask for the whole QBCore resource shape

A useful QBCore response should make the file boundaries obvious. For many resources that means fxmanifest.lua, config.lua, client logic and server logic, plus any item, SQL or dependency notes your stack needs. Keep framework-specific calls in the right layer rather than mixing unrelated exports from different inventories or menu systems.

Client

Targets, menus, animations, key input and visual feedback belong on the client. The client can request an action but should not award money or inventory.

Server

Validate jobs, items, locations, cooldowns, permissions and rewards on the server using the installed QBCore and inventory APIs.

Config

Keep item names, prices, locations, job grades and tunable values in configuration so balancing changes do not require rewriting core logic.

Test the failure cases before your live server

Run generated resources on a development server first. Try missing dependencies, wrong item names, invalid job grades, repeated network events, two players using the same interaction and resource restarts. Watch both client and server consoles, then bring the exact error back for a focused fix.
