How to add leaderstats to your Roblox game

UPDATED 18 AUGUST 2026 · 7 MIN READ · STELLAR AI

Leaderstats are Roblox’s built-in way to show a small set of player stats on the in-game leaderboard. They are useful for showing coins, wins, rebirths or level—but they are only the display layer. Your game still needs server-side logic and persistent player data behind them.

What leaderstats should show

Only display values that help a player understand their progress or compare a meaningful achievement. Coins, wins, kills, rebirths and level are common examples. Avoid putting every saved value on the leaderboard; capacity, internal upgrade levels, equipped items and private settings usually belong in your player data or UI instead.

Important distinction: leaderstats show values in Roblox’s player list. They do not automatically save data, balance an economy, or protect a game from exploit attempts.

Create the leaderboard from a server Script

Create a normal Script inside ServerScriptService. Keeping this on the server makes the leaderboard available to every player and stops the client from being the source of truth.

local Players = game:GetService("Players") Players.PlayerAdded:Connect(function(player) local leaderstats = Instance.new("Folder") leaderstats.Name = "leaderstats" leaderstats.Parent = player local coins = Instance.new("IntValue") coins.Name = "Coins" coins.Value = 0 coins.Parent = leaderstats local rebirths = Instance.new("IntValue") rebirths.Name = "Rebirths" rebirths.Value = 0 rebirths.Parent = leaderstats end)

The exact folder name matters: Roblox recognises a folder called leaderstats. Each value inside it then appears in the standard player list when a player joins.

Update stats through gameplay, not the client

When a player earns coins, the server should verify the action and update the value. For a simulator, that could mean checking the player is close to a collection object, has not exceeded a cooldown, and has not reached backpack capacity before adding currency.

local function awardCoins(player, amount) local leaderstats = player:FindFirstChild("leaderstats") local coins = leaderstats and leaderstats:FindFirstChild("Coins") if not coins then return end coins.Value += amount end

Do not let a LocalScript send a number such as “give me 5000 coins” and apply it directly. The client can request an action, but the server should calculate and approve the reward.

Connect leaderstats to saved player data

For a game that players return to, load persistent data when the player joins and apply the saved values to leaderstats. Save progress again when the player leaves and at controlled points during a session. Roblox DataStores are intended for persistent experience data, but calls can fail, so handle failures without erasing existing progress. [1]

Load a default profile for a new player.
Use protected calls around every data load and save.
Only show stats after your server has loaded the player profile.
Never replace old data with blanks after a failed load.

As your project grows, keep a dedicated player-data module as the source of truth. Update the visible leaderstats whenever the player’s coins or rebirths change. This makes it easier to add UI, shops, game passes and separate internal stats later.

Test it in Studio

Start a two-player local server test in Roblox Studio. Confirm that both players get their own values, that an earned reward only changes the correct player, and that one player cannot affect another player’s stats. Test a fresh player, a returning player, and the case where a data request fails.

For a simulator, also test the full loop: collect currency, reach capacity, sell, buy an upgrade, leave, and return. The leaderboard should reflect real progress rather than become the system that creates it.
