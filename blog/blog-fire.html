QBCore Fire Job — Build a server-authoritative fire department for FiveM (plus Roblox pattern)

Updated September 2026 · 8 min read · Stellar AI

This guide walks you through a secure, production-minded QBCore Fire Job resource for FiveM, plus a short Roblox pattern that maps to the same responsibilities. It focuses on server authority, validation, job/on-duty gating, target interactions, and safe persistence. Wherever appropriate the examples follow QBCore and Roblox server-client rules.

Implementation plan (short)

1) Create a QBCore resource with fxmanifest.lua, config.lua, client.lua and server.lua. 2) Use qb-target or ox_lib for interactions. 3) Keep all authoritive state and rewards server-side. 4) Offer a Roblox-compatible pattern using RemoteEvents and DataStore with retry handling. 5) Validate, test, and iterate.

Assumptions and dependencies

  • FiveM: QBCore (v2 style exports), qb-target or ox_lib, optional qb-phone or dispatch integration.
  • Roblox: standard server-client model, DataStoreService available, RemoteEvent/RemoteFunction allowed.
  • You have permission to add/start resources on the target server and to create Roblox scripts in a place you control.

QBCore Fire Job — Files and where they go

Place the resource in your server/resources folder as qb-firejob. Ensure it is started after qb-core and qb-target.

  'qb-core',

config.lua

Config = {}
Config.JobName = 'fire'
Config.ExtinguishPay = 150 -- server-side validated
Config.MinimumRank = 0 -- lowest rank allowed to earn pay
Config.Targets = {
  ['firehose'] = { coords = vector3(256.0, -1002.0, 29.3), dist = 2.0 }
}

server.lua (core validation)

local QBCore = exports['qb-core']:GetCoreObject()

RegisterNetEvent('qb-firejob:server:Extinguish', function(zone)
  local src = source
  local Player = QBCore.Functions.GetPlayer(src)
  if not Player then return end

  -- Server-side job check and on-duty enforcement
  local job = Player.PlayerData.job
  if not job or job.name ~= Config.JobName then
    TriggerClientEvent('QBCore:Notify', src, 'You are not a firefighter', 'error')
    return
  end
  if job.onduty ~= true then
    TriggerClientEvent('QBCore:Notify', src, 'You must be on duty', 'error')
    return
  end
  if job.grade < Config.MinimumRank then
    TriggerClientEvent('QBCore:Notify', src, 'Your rank cannot claim rewards', 'error')
    return
  end

  -- Award and log server-side
  local pay = Config.ExtinguishPay
  Player.Functions.AddMoney('bank', pay, 'fire-extinguish')
  TriggerClientEvent('QBCore:Notify', src, ('Paid $%s for extinguishing'):format(pay), 'success')

  -- Optional: trigger dispatch, logs, brief cooldowns, etc.
end)

-- Safe server callback example for UI
QBCore.Functions.CreateCallback('qb-firejob:server:GetStatus', function(source, cb)
  local Player = QBCore.Functions.GetPlayer(source)
  if not Player then cb({ok = false}) return end
  cb({job = Player.PlayerData.job})
end)

Notes: always validate Player.PlayerData.job and job.onduty server-side before changing money or persistent state. Do not trust client-sent zone names without validation.

client.lua (qb-target example)

local QBCore = exports['qb-core']:GetCoreObject()

CreateThread(function()
  for name,data in pairs(Config.Targets) do
    exports['qb-target']:AddBoxZone(name, data.coords, 1.5, 1.5, {
      name = name,
      heading = 0,
      debugPoly = false,
      minZ = data.coords.z - 1.0,
      maxZ = data.coords.z + 1.0
    }, {
      options = {{
        type = 'client',
        event = 'qb-firejob:client:UseHose',
        icon = 'fas fa-fire-extinguisher',
        label = 'Use firehose'
      }},
      distance = data.dist
    })
  end
end)

RegisterNetEvent('qb-firejob:client:UseHose', function()
  QBCore.Functions.TriggerCallback('qb-firejob:server:GetStatus', function(resp)
    if not resp or not resp.job or resp.job.name ~= Config.JobName or resp.job.onduty ~= true then
      QBCore.Functions.Notify('You must be on duty as a firefighter', 'error')
      return
    end
    -- Play animation, particles, then notify server to award
    -- animation omitted for brevity
    TriggerServerEvent('qb-firejob:server:Extinguish', 'firehose')
  end)
end)

Use qb-target to limit interactions only when physically near tools or vehicles. Keep asset spawning and ownership checks on the server.

Roblox pattern: server-authoritative Fire Job

The same responsibilities exist on Roblox: keep award logic and job assignment on the server, use RemoteEvents to request actions, and use DataStore with pcall and retries for persistence.

Files (place in ServerScriptService / ReplicatedStorage)

  • ReplicatedStorage.FireEvent (RemoteEvent)
  • ServerScriptService.FireServer (Script)
  • StarterPlayerScripts.FireClient (LocalScript)

ServerScriptService/FireServer.lua (safe, simplified)

-- ServerScriptService/FireServer.lua
local ReplicatedStorage = game:GetService('ReplicatedStorage')
local Players = game:GetService('Players')
local DataStoreService = game:GetService('DataStoreService')
local fireEvent = ReplicatedStorage:WaitForChild('FireEvent')
local jobStore = DataStoreService:GetDataStore('PlayerJobs')

local function updateDataStore(player, key, transform)
  local success, err
  for i=1,3 do
    success, err = pcall(function()
      jobStore:UpdateAsync(player.UserId .. ':' .. key, function(old)
        return transform(old)
      end)
    end)
    if success then return true end
    wait(1 * i) -- exponential-ish backoff
  end
  warn('DataStore update failed for', player.Name, err)
  return false
end

fireEvent.OnServerEvent:Connect(function(player, action)
  -- Validate player's job server-side
  local jobMeta = player:GetAttribute('Job') or 'none'
  local onduty = player:GetAttribute('OnDuty')
  if jobMeta ~= 'Fire' or not onduty then
    fireEvent:FireClient(player, 'Denied')
    return
  end

  if action == 'Extinguish' then
    -- award XP or money in a server-authoritative way
    local awarded = 50
    player:SetAttribute('Cash', (player:GetAttribute('Cash') or 0) + awarded)
    local ok = updateDataStore(player, 'cash', function(old)
      return (old or 0) + awarded
    end)
    fireEvent:FireClient(player, ok and 'Success' or 'SavedLocally')
  end
end)

Security considerations & next steps

  • Never award money client-side. Always check Player.PlayerData.job on server.
  • Consider rate-limiting extinguish events per player to avoid farming.
  • Add logging to an external audit channel for suspicious patterns.
  • For Roblox, respect DataStore limits and use UpdateAsync with retries.

Next steps: hook dispatch/notifications, create grade-based tasks, add vehicle garage management server-side, and plan telemetry for balancing rewards. Test each change on a staging server before moving to live.
