FiveM NUI Not Opening? HTML, Focus and Callback Debugging Guide

Fix FiveM NUI pages that do not open by checking ui_page files, SendNUIMessage, SetNuiFocus, JavaScript events and NUI callbacks.

Stellar AI · Updated 27 September 2026

Verify fxmanifest NUI files

Your fxmanifest.lua must declare the ui_page and include the HTML, JavaScript, CSS and asset files needed by the interface. A missing file entry can leave the page blank or partially broken.

Open the in-game developer tools while testing to catch missing assets and JavaScript errors.

Prove the Lua message is being sent

Add one temporary client log immediately before SendNUIMessage. If the log never appears, the problem is your Lua event or condition rather than the web UI.

Then add a browser-side console log inside the message event listener to confirm the message arrives.

Check SetNuiFocus separately

The UI can render while the player still cannot click it if focus is never set. Conversely, leaving focus enabled after closing the interface can trap keyboard or mouse input.

Treat visibility state and focus state as two separate things and update both during open and close flows.

Match message names and payload keys

The Lua table sent through SendNUIMessage becomes data for your JavaScript listener. If Lua sends action = 'openMenu' but JavaScript checks for 'open', nothing happens.

Use a small documented message contract so future changes do not silently drift.

Debug NUI callbacks end to end

For buttons that call back into Lua, confirm the fetch URL or callback name matches RegisterNUICallback and that the callback always returns a response.

When a button appears to freeze, inspect both the browser console and FiveM client console before changing unrelated code.

Use a minimal reproduction.

Before changing a large project, reproduce the problem with the fewest files and dependencies possible. This makes the real cause easier to identify and makes AI-assisted debugging much more reliable.
