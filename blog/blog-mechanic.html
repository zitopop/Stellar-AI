QBCore Mechanic Job — Plan, Files, and Secure Implementation

Updated September 2026 · 8 min read · Stellar AI

This guide walks a builder through a compact, secure implementation of a mechanic job for QBCore. You get an implementation plan, assumptions, complete resource files, installation steps, and a verification checklist so the mechanic role behaves correctly and money/item changes are enforced server-side.

Overview & implementation plan

Mechanic jobs in QBCore should be server-authoritative: the server decides whether a player is a mechanic, removes payment or items, and then instructs a client to apply the repair to the vehicle. The plan below builds a small resource named qb-mechanic that provides a useable repairkit item and a repair flow that validates the player's job and funds server-side.

Plan

  • Create a self-contained resource (fxmanifest, config, client, server)
  • Register a useable item on the server (repairkit) that triggers the client
  • Client finds the nearest vehicle and requests server authorization
  • Server validates job and money/items; on success, instructs client to repair
  • Provide clear installation and validation steps plus an optional qb-target hook

Assumptions and dependencies

Assumes a QBCore v2-style server with exports['qb-core']:GetCoreObject(). Optional integrations: qb-target (for target interactions). The code uses common QBCore server APIs (CreateUseableItem, GetPlayer, CreateCallback) and FiveM natives for nearby vehicle detection and repair. If your server uses a different money/item API, adapt the server functions where payment/item removal and notifications happen.

Complete resource files (destination-labelled)

Drop this folder into your server resources and add start qb-mechanic to server.cfg.

// fxmanifest.lua
fx_version 'cerulean'
game 'gta5'

author 'you'
description 'QBCore mechanic job — minimal secure example'
version '1.0.0'

shared_script 'config.lua'

server_scripts {
  'server.lua'
}

client_scripts {
  'client.lua'
}

depends {
  'qb-core'
}

// config.lua
Config = {}
Config.RepairCost = 200 -- price charged to mechanic for each repair (adjust to your economy)
Config.MechanicJob = 'mechanic' -- job name used in qb-core/shared/jobs.lua
Config.MaxDistance = 5.0 -- max meters to vehicle for repair

// server.lua
local QBCore = exports['qb-core']:GetCoreObject()

-- Simple callback to check job
QBCore.Functions.CreateCallback('qb-mechanic:server:isMechanic', function(source, cb)
    local Player = QBCore.Functions.GetPlayer(source)
    if Player and Player.PlayerData and Player.PlayerData.job then
        cb(Player.PlayerData.job.name == Config.MechanicJob)
    else
        cb(false)
    end
end)

-- Register a useable item called 'repairkit' — add the item to your shared/items.lua if missing
QBCore.Functions.CreateUseableItem('repairkit', function(source)
    TriggerClientEvent('qb-mechanic:client:useRepairKit', source)
end)

-- Server event: validate and process repair request
RegisterNetEvent('qb-mechanic:server:requestRepair', function(netVehicleId)
    local src = source
    local Player = QBCore.Functions.GetPlayer(src)
    if not Player then return end

    if Player.PlayerData.job.name ~= Config.MechanicJob then
        TriggerClientEvent('QBCore:Notify', src, 'You are not a mechanic', 'error')
        return
    end

    -- Charge the mechanic (server authoritative)
    local price = Config.RepairCost
    local success = Player.Functions.RemoveMoney('bank', price)
    if not success then
        TriggerClientEvent('QBCore:Notify', src, 'Not enough money', 'error')
        return
    end

    -- Optionally remove an item (repairkit) if you want one-time use
    Player.Functions.RemoveItem('repairkit', 1)

    -- Instruct client to perform repair (client will validate network id exists locally)
    TriggerClientEvent('qb-mechanic:client:doRepair', src, netVehicleId)
    TriggerClientEvent('QBCore:Notify', src, 'Vehicle repaired — charged $' .. price, 'success')
end)

// client.lua
local QBCore = exports['qb-core']:GetCoreObject()

-- Called when player uses a repairkit
RegisterNetEvent('qb-mechanic:client:useRepairKit', function()
    QBCore.Functions.TriggerCallback('qb-mechanic:server:isMechanic', function(isMech)
        if not isMech then
            QBCore.Functions.Notify('You must be a mechanic to use this', 'error')
            return
        end

        -- find nearest vehicle
        local playerPed = PlayerPedId()
        local pCoords = GetEntityCoords(playerPed)
        local vehicle = GetClosestVehicle(pCoords.x, pCoords.y, pCoords.z, Config.MaxDistance, 0, 70)
        if not DoesEntityExist(vehicle) then
            QBCore.Functions.Notify('No vehicle nearby', 'error')
            return
        end

        local netId = NetworkGetNetworkIdFromEntity(vehicle)
        -- request server to charge and validate
        TriggerServerEvent('qb-mechanic:server:requestRepair', netId)
    end)
end)

-- Server-authorized repair triggered here
RegisterNetEvent('qb-mechanic:client:doRepair', function(netId)
    local vehicle = NetworkGetEntityFromNetworkId(netId)
    if not vehicle or not DoesEntityExist(vehicle) then
        QBCore.Functions.Notify('Vehicle no longer available', 'error')
        return
    end

    -- Simple visual: fix and set engine health
    SetVehicleFixed(vehicle)
    SetVehicleEngineHealth(vehicle, 1000.0)
    QBCore.Functions.Notify('Repair complete', 'success')
end)

Installation & configuration

  1. Place the folder qb-mechanic in your resources directory.
  2. Ensure the resource is started in server.cfg: start qb-mechanic.
  3. If you don't have a repairkit item, add it to qb-core/shared/items.lua (or add a shop entry).
  4. Restart the server and test with a test mechanic account.

Validation, security notes, and testing checklist

Put all authoritative checks on the server. Do not allow the client to deduct money or spawn receipts. Use the checklist below to validate behavior before giving players access.

Step What to check
Job validation Player must be mechanic server-side before charging/repairing
Payment The server removes money or item; client only requests repair
Vehicle validity Client validates the vehicle entity exists for the supplied network ID
Race/Exploit checks Ensure server rejects requests that come from non-mechanics or when item/money removal fails

Quick testing steps

  • Create a player with job mechanic and one without, then try using the repairkit.
  • Attempt to trigger the server event from a non-mechanic client (should be rejected).
  • Try with insufficient funds — server should not call client repair.
