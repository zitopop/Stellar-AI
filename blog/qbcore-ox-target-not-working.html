QBCore ox_target Not Working: FiveM Troubleshooting Guide

Fix ox_target interactions in QBCore by checking resource order, exports, zones, models, permissions, distances and client-side registration.

Stellar AI · Updated 27 September 2026

Confirm ox_target starts before your resource

If your script calls ox_target exports before ox_target is available, registration can fail or throw an export error. Check the server start order and any dependencies in fxmanifest.lua.

Also confirm the resource name is exactly the one your code expects. Renamed folders can break exports.

Check whether the target is actually registered

Add one temporary log immediately after your addBoxZone, addSphereZone, addModel or entity registration. If the script never reaches that line, the problem is earlier in the client file.

For model targets, confirm the model hash or name is correct and that the entity exists when registration occurs.

Review distance, coordinates and zone size

A target can be technically registered but impossible to hit if the zone is tiny, underground or offset from the intended object. Temporarily make the zone larger and raise the interaction distance while debugging.

Once it works, tighten the values back to the intended experience.

Separate visibility rules from action rules

Job, gang or item checks can hide the interaction before a user ever sees it. Temporarily remove restrictive canInteract or group conditions to prove the base target works, then add conditions back one at a time.

Important rewards and permissions should still be revalidated on the server even when the target is hidden client-side.

Check callback context and exports

If the eye opens but clicking does nothing, inspect the onSelect callback, event name or export it calls. Confirm whether the action is client-side or server-side and use the correct event direction.

Keep the smallest reproducible target example in your development resource so you can compare future failures quickly.

Use a minimal reproduction.

Before changing a large project, reproduce the problem with the fewest files and dependencies possible. This makes the real cause easier to identify and makes AI-assisted debugging much more reliable.
