FiveM ox_inventory Item Not Working: QBCore Fix Checklist

Troubleshoot ox_inventory items that do not appear, cannot be used or have broken metadata in QBCore/FiveM resources.

Stellar AI · Updated 27 September 2026

Check the item definition first

Make sure the item name used by your script exactly matches the item definition. Case differences, spaces or a renamed item can make inventory operations silently fail or return nil.

If you migrated from qb-inventory, do not assume every old item field maps directly to ox_inventory.

Verify the correct inventory API

Scripts written for another inventory may call functions or exports that ox_inventory does not provide. Identify every add, remove, search and metadata call used by the resource and adapt the integration layer rather than mixing APIs.

A small inventory adapter can make future migrations much easier.

Confirm image and UI assets separately

An item can exist in data but still display badly because its image path or metadata renderer is wrong. Test whether the server can add the item before debugging the UI asset.

This keeps a cosmetic problem from being mistaken for an inventory-state problem.

Validate usable-item behaviour

If an item appears but cannot be used, check where its use action is registered and whether the callback runs on the expected side. Log the item name and metadata received by the callback.

Any reward, money or privileged action triggered by item use should still be validated server-side.

Test metadata and stacking rules

Items with different metadata may stack differently from plain items. If a serial number, quality value or custom field is missing, search and remove calls may not match what you expect.

Print a sanitized representation of the item slot during development so you can compare the actual metadata with the query your script sends.

Retest the complete item flow

After the fix, test the item from creation through use: confirm it exists in the item definition, appears in the inventory, can be transferred if intended and reaches the correct server-side handler. Test with a normal player account as well as an administrator. This catches permission, metadata and callback problems that a single successful spawn can hide.

Use a minimal reproduction.

Before changing a large project, reproduce the problem with the fewest files and dependencies possible. This makes the real cause easier to identify and makes AI-assisted debugging much more reliable.
