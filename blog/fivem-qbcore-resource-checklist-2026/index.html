FiveM QBCore Resource Checklist for 2026

A good FiveM resource is not just a Lua file that starts. It needs a clear folder shape, predictable configuration, server-side authority and test notes that catch boring problems before players do.

Start with the resource shape

  • Keep fxmanifest.lua, config.lua, client files, server files and README notes separate.
  • Name dependencies explicitly: QBCore, ox_lib, ox_inventory, qb-target or any database resource the script needs.
  • Put prices, cooldowns, coordinates, job names and grade rules in config instead of burying them inside gameplay logic.

Split client and server work properly

  • Client code should handle UI, markers, menus and local feedback.
  • Server code should validate money, items, jobs, grades, cooldowns and rewards.
  • Never trust a client event just because the button was hidden from normal players.

Add release checks before going live

  • Restart the resource twice and check for missing exports, nil values and dependency timing problems.
  • Test rejected paths: wrong job, wrong grade, no item, no money, cooldown active and player too far away.
  • Write a short README with install steps, required resources and the events or commands included.
