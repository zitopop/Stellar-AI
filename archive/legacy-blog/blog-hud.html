QBCore HUD — NUI-based, server-aware, secure

QBCore HUD Customisation: Practical Guide for Builders

Updated September 2026 · 8 min read · Stellar AI

Customize a modern QBCore HUD using a small NUI (HTML/CSS/JS) overlay with client-server best practices. This guide gives a short implementation plan, lists assumptions, provides complete destination-labelled files, and explains installation, validation and security considerations so you can ship a maintainable HUD on your FiveM server.

Implementation plan (short)

1) Create a resource with fxmanifest.lua, a client script, a minimal server script, a config file, and an html UI directory. 2) Use exports['qb-core']:GetCoreObject() on the client to subscribe to player events and send periodic state to the NUI. 3) Keep authoritative checks server-side: money changes, health-affecting effects or sensitive data must always be validated by server callbacks. 4) Provide feature toggle in config and graceful fallback if the NUI is unavailable.

Assumptions & framework dependencies

  • Server runs a supported QBCore release where exports['qb-core']:GetCoreObject() is available.
  • You will use a client-side NUI to render the HUD so it works cross-client and supports CSS animations.
  • Sensitive changes (add/remove money, admin-only toggles) remain server-side and are not trusted from the client or NUI.
  • This example avoids ox_lib or qb-target specific code; add hooks where you already use those libraries.

Files you'll create (complete destination-labelled files)

Place these files in a resource directory, e.g. resources/[local]/qb-hud-custom

fxmanifest.lua

fx_version 'cerulean'
game 'gta5'

author 'YourName'
description 'QBCore Custom HUD (NUI)'
version '1.0.0'

shared_script 'config.lua'

client_script 'client/main.lua'
server_script 'server/main.lua'

ui_page 'html/ui/index.html'

files {
  'html/ui/index.html',
  'html/ui/style.css',
  'html/ui/app.js'
}

config.lua

Config = {}
Config.UpdateInterval = 1000 -- ms, how often client sends state to NUI
Config.ShowHunger = true
Config.ShowThirst = true

client/main.lua

local QBCore = exports['qb-core']:GetCoreObject()
local playerData = {}

local function SendHudUpdate(data)
  SendNUIMessage({action = 'updateHUD', payload = data})
end

-- Subscribe to player loaded and job updates
RegisterNetEvent('QBCore:Client:OnPlayerLoaded', function()
  playerData = QBCore.Functions.GetPlayerData()
  SendHudUpdate({player = playerData})
end)

RegisterNetEvent('QBCore:Client:OnJobUpdate', function(job)
  playerData.job = job
  SendHudUpdate({player = playerData})
end)

-- Periodic state: health, armor, status effects, hunger/thirst if provided by a status resource
Citizen.CreateThread(function()
  while true do
    local ped = PlayerPedId()
    local health = GetEntityHealth(ped)
    local armour = GetPedArmour(ped)

    -- If you use a hunger/thirst resource, fetch it safely instead of trusting NUI input
    local status = {}
    if Config.ShowHunger then status.hunger = exports['status']:Get('hunger') or 0 end
    if Config.ShowThirst then status.thirst = exports['status']:Get('thirst') or 0 end

    local data = {
      health = health,
      armour = armour,
      job = playerData.job,
      money = playerData.money, -- local read of player data; authoritative changes must come from server
      status = status
    }

    SendHudUpdate(data)
    Citizen.Wait(Config.UpdateInterval)
  end
end)

server/main.lua

local QBCore = exports['qb-core']:GetCoreObject()

-- Example server callback for validated money change
QBCore.Functions.CreateCallback('qb-hud:server:GetPlayerMoneySafe', function(source, cb, targetPlayer)
  local src = source
  local Player = QBCore.Functions.GetPlayer(targetPlayer or src)
  if Player then
    cb({cash = Player.PlayerData.money['cash'], bank = Player.PlayerData.money['bank']})
  else
    cb(nil)
  end
end)

Note: The server callback above shows how to avoid trusting client-sent money values. Callbacks are the proper way to retrieve authoritative data when the client UI needs to show accurate balances.

    <div id="status">H: -- T: -- </div>
  </div>
  <script src="app.js"></script>
</body>

html/ui/app.js (listens for SendNUIMessage)

window.addEventListener('message', function(event) {
  const d = event.data
  if (d.action === 'updateHUD') {
    const p = d.payload
    document.getElementById('health').innerText = 'Health: ' + (p.health || '--')
    document.getElementById('money').innerText = 'Cash: ' + ((p.money and p.money.cash) || '--')
    if (p.status) document.getElementById('status').innerText = 'H: ' + (p.status.hunger || 0) + ' T: ' + (p.status.thirst || 0)
  }
})

Installation & where files belong

  1. Create a folder resources/[local]/qb-hud-custom and place fxmanifest.lua and config.lua at its root.
  2. Create client/main.lua and server/main.lua in client/ and server/ subfolders respectively (or named as above and referenced by fxmanifest).
  3. Create html/ui/ with index.html, style.css and app.js. Ensure fxmanifest lists these files and ui_page points to index.html.
  4. Add start qb-hud-custom to your server.cfg after qb-core.

Security and best practices

  • Never accept monetary or admin state from the client. Always verify via server callbacks or events.
  • Keep any privileged server events protected by permission checks (isPlayerAceAllowed or QBCore permissions).
  • Sanitise any strings sent to the NUI to avoid malformed HTML; prefer plain text insertion (textContent in JS).
  • Avoid heavy UI updates every tick. Use coalesced updates (e.g., 500–2000 ms) or delta changes.
