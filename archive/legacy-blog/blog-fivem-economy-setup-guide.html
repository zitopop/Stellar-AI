FiveM Economy Setup Guide — Secure, Server‑Authoritative, QBCore Example

Updated September 2026 · 8 min read · Stellar AI

This guide walks you through designing and implementing a secure, server‑authoritative economy on FiveM using QBCore patterns. You’ll get a short implementation plan, assumptions, complete destination-labelled files, installation steps, a validation checklist, and safe code examples you can drop into a resource.

Overview

Creating a believable and secure economy in FiveM is about more than numbers: it’s about server authority, consistent state, anti‑exploit validation, and extensible APIs for shops, jobs, and persistence. This guide shows a minimal, robust pattern for QBCore servers: all balance changes happen server‑side, client requests use validated server events/callbacks, and configuration is separated from logic so you can plug in banks, item shops, or job paychecks later.

Implementation plan (short)

  • Define a small API: server events and callbacks for GiveMoney, RemoveMoney, and GetBalance.
  • Implement server‑side validation using QBCore’s player object and permissions.
  • Create a safe client interface for UI or in‑game interactions.
  • Test edge cases, persistence, and abuse scenarios.

Assumptions & framework dependencies

  • Server runs QBCore (v1 compatible) and has the usual player object functions (e.g., QBCore.Functions.GetPlayer).
  • Money is stored as an integer (no floats) and QBCore exports handle adding/removing cash/bank.
  • You have basic resource deployment rights and can add/ensure fxmanifest.lua is loaded.

Files you will add (destination-labelled)

Below are complete files for a minimal resource named qb-economy-api. Place the folder under your server resources and add it to server.cfg.

-- qb-economy-api/fxmanifest.lua
fx_version 'cerulean'
games { 'gta5' }

author 'YourName'
description 'Minimal QBCore economy API'
version '1.0.0'

shared_script 'config.lua'
server_script 'server/main.lua'
client_script 'client/main.lua'

-- qb-economy-api/config.lua
Config = {}
Config.LogTransactions = true -- set to false in production noisy servers
Config.SafeMaxChange = 1000000 -- max amount allowed in a single change

-- qb-economy-api/server/main.lua
local QBCore = exports['qb-core']:GetCoreObject()

-- Server callback to get balance
QBCore.Functions.CreateCallback('qb-economy:getBalance', function(source, cb)
    local player = QBCore.Functions.GetPlayer(source)
    if not player then return cb(nil) end
    local cash = player.Functions.GetMoney('cash')
    local bank = player.Functions.GetMoney('bank')
    cb({ cash = cash, bank = bank })
end)

-- Secure money change event
RegisterNetEvent('qb-economy:changeMoney', function(type, amount, reason)
    local src = source
    local player = QBCore.Functions.GetPlayer(src)
    if not player then return end
    amount = tonumber(amount) or 0
    if amount == 0 then return end

    -- Basic validation
    if math.abs(amount) > Config.SafeMaxChange then
        print(('qb-economy: blocked huge money change from %s (%s)'):format(src, amount))
        return
    end

    -- Only server‑side functions actually change money
    if amount > 0 then
        player.Functions.AddMoney(type, amount, reason or 'server:forceAdd')
    else
        -- Removing money: ensure player has funds
        local cur = player.Functions.GetMoney(type)
        if cur + amount < 0 then
            -- Not enough funds (amount is negative)
            TriggerClientEvent('QBCore:Notify', src, 'Insufficient funds', 'error')
            return
        end
        player.Functions.RemoveMoney(type, math.abs(amount), reason or 'server:forceRemove')
    end

    if Config.LogTransactions then
        print(('qb-economy: %s %s %s by %s'):format(type, amount, reason or '-', player.PlayerData.citizenid))
    end
end)

-- qb-economy-api/client/main.lua
-- Example client call to request a purchase
function TryPurchase(itemPrice)
    -- Ask server for current balance first (avoid desync expectations)
    QBCore.Functions.TriggerCallback('qb-economy:getBalance', function(balance)
        if not balance then return end
        if balance.cash >= itemPrice then
            -- Ask server to remove cash securely
            TriggerServerEvent('qb-economy:changeMoney', 'cash', -itemPrice, 'item_purchase')
        else
            QBCore.Functions.Notify('Not enough cash', 'error')
        end
    end)
end

Core concepts explained

Always treat the server as source of truth. Clients can request actions but must never apply balance changes locally. Use callbacks to fetch authoritative state and RegisterNetEvent on the server to make changes after full checks. Keep business logic on the server (job pay, marketplace settlement). The client can only present UI and call validated server endpoints.

Installation & deployment

  1. Place the folder qb-economy-api in your server resources directory.
  2. Add start qb-economy-api to server.cfg (after qb-core).
  3. Restart or refresh the resource and test with two connected players to verify concurrency behavior.

Practical checklist: Security & validation

ItemWhy it mattersPass/Fail
All money changes only on serverPrevents client spoofing
Max per‑change limitStops single huge exploit attempts
Balance check before removalPrevents negative exploits
Server log for suspicious changesEnables auditing
Rate limit high‑frequency endpointsPrevents spam or DDoS

Testing & common edge cases

  • Test concurrent purchases: two players buying the same unique item should be resolved server‑side.
  • Test negative and huge amounts: ensure the server rejects them and logs.
  • Persistence: if your economy interacts with a database, test transaction rollback on failure.
