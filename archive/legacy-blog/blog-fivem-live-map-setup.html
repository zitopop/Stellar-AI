FiveM Live Map Setup — Server-Authoritative Real-Time Player Map

Updated September 2026 · 8 min read · Stellar AI

This guide walks a FiveM developer through a practical, secure setup to stream player positions to an external live map. The pattern is server-authoritative: clients send position updates to the server, the server validates and aggregates, and a small bridge forwards positions to a web map over WebSocket. Complete file examples and deployment steps are included.

Why server-authoritative live maps?

External live maps are useful for administration, events, and public status pages. A server-authoritative pipeline prevents client spoofing, implements rate limiting, and centralises access controls. The pattern below keeps trust on the FiveM server, uses a separate web bridge for public display, and leaves secrets out of client code.

Implementation plan (short)

  1. Create a FiveM resource that accepts periodic client coordinate updates and validates them.
  2. Store a compact player state on the server and periodically POST the aggregated snapshot to a Node.js bridge using a server-side secret.
  3. The Node.js bridge broadcasts snapshots to connected web clients via WebSocket; a Leaflet front-end renders markers.

Assumptions & framework dependencies

  • Vanilla FiveM server with Lua resources. QBCore/ESX users: the examples use only core FiveM functions (GetPlayerName, source) so they work alongside frameworks. If you need framework-specific player metadata, call QBCore or ESX server APIs when building the snapshot.
  • External map host reachable from your FiveM server (the bridge). Use a private bridge (local network) for staff-only maps, or host in a secure VPS for public maps.
  • Node.js 16+ for the bridge and a small static web host for the Leaflet page.

Files you will create

Below are full destination-labelled files. Put the FiveM files into a resource folder (e.g. resources/[local]/live_map). The Node and web files are deployed outside FiveM.

1) fxmanifest.lua (resource root)

fx_version 'cerulean'
games { 'gta5' }

shared_script 'config.lua'

2) config.lua

-- live_map/config.lua
Config = {
  UpdateInterval = 2000,          -- how often client sends coords (ms)
  ServerBroadcastInterval = 3000, -- server pushes snapshot to bridge (ms)
  BridgeUrl = GetConvar('live_map_bridge', 'http://127.0.0.1:8080/update'),
  BridgeSecretConvar = 'live_map_secret'
}

3) client.lua

-- live_map/client.lua
local sendInterval = Config.UpdateInterval
Citizen.CreateThread(function()
  while true do
    Citizen.Wait(sendInterval)
    local ped = PlayerPedId()
    if DoesEntityExist(ped) then
      local pos = GetEntityCoords(ped)
      TriggerServerEvent('live_map:updateCoords', { x = pos.x, y = pos.y, z = pos.z })
    end
  end
end)

4) server.lua

-- live_map/server.lua
local playerPositions = {}

RegisterNetEvent('live_map:updateCoords', function(coords)
  local src = source
  if type(coords) ~= 'table' or not coords.x or not coords.y or not coords.z then return end

  -- Basic validation
  for k,v in pairs(coords) do
    if type(v) ~= 'number' or math.abs(v) > 100000 then return end
  end

  playerPositions[src] = {
    id = src,
    name = GetPlayerName(src) or ('player_'..src),
    x = coords.x,
    y = coords.y,
    z = coords.z,
    ts = os.time()
  }
end)

Citizen.CreateThread(function()
  while true do
    Citizen.Wait(Config.ServerBroadcastInterval)
    local snapshot = {}
    for src, data in pairs(playerPositions) do
      -- drop stale entries older than 10s
      if os.time() - data.ts < 10 then
        table.insert(snapshot, data)
      else
        playerPositions[src] = nil
      end
    end

    if #snapshot > 0 then
      local payload = json.encode({ players = snapshot })
      local secret = GetConvar(Config.BridgeSecretConvar, '')
      PerformHttpRequest(Config.BridgeUrl, function(code, res, headers) end, 'POST', payload, { ['Content-Type'] = 'application/json', ['X-Live-Map-Secret'] = secret })
    end
  end
end)

5) Node.js bridge (map_server/index.js)

// map_server/index.js
const express = require('express')
const bodyParser = require('body-parser')
const WebSocket = require('ws')

const app = express()
app.use(bodyParser.json())

const PORT = process.env.PORT || 8080
const SECRET = process.env.LIVE_MAP_SECRET || 'replace-me'

const wss = new WebSocket.Server({ noServer: true })
let lastSnapshot = { players: [] }

app.post('/update', (req, res) => {
  const secret = req.header('X-Live-Map-Secret') || ''
  if (secret !== SECRET) return res.status(401).send('unauthorized')
  if (!req.body || !Array.isArray(req.body.players)) return res.status(400).send('bad payload')

  lastSnapshot = req.body
  // broadcast to WS clients
  const msg = JSON.stringify(lastSnapshot)
  wss.clients.forEach(c => { if (c.readyState === WebSocket.OPEN) c.send(msg) })
  res.send('ok')
})

const server = app.listen(PORT, () => console.log('bridge listening', PORT))
server.on('upgrade', (req, socket, head) => {
  wss.handleUpgrade(req, socket, head, ws => wss.emit('connection', ws, req))
})

// optional: provide last snapshot for HTTP polling
app.get('/snapshot', (req, res) => res.json(lastSnapshot))

6) Web front-end (web/index.html)

<!doctype html>
<html><head>
  <meta charset="utf-8"/>
  <title>Live Map</title>
  <link rel="stylesheet" href="https://unpkg.com/leaflet/dist/leaflet.css"/>
</head><body>
  <div id="map" style="width:100%;height:100vh"></div>
  <script src="https://unpkg.com/leaflet/dist/leaflet.js"></script>
  <script>
    const map = L.map('map').setView([0,0], 2)
    L.tileLayer('https://{s}.tile.openstreetmap.org/{z}/{x}/{y}.png',{maxZoom:19}).addTo(map)
    const markers = {}
    const ws = new WebSocket('ws://YOUR_BRIDGE_HOST:8080')

    ws.onmessage = (e) => {
      const data = JSON.parse(e.data)
      data.players.forEach(p => {
        const latLng = [p.y, p.x] // swap if your mapping uses lat/lon; adjust as needed
        if (markers[p.id]) {
          markers[p.id].setLatLng(latLng)
        } else {
          markers[p.id] = L.marker(latLng).addTo(map).bindPopup(p.name)
        }
      })
    }
  </script>
</body></html>

Where each file belongs and installation

  • Put fxmanifest.lua, client.lua, server.lua, config.lua into resources/[local]/live_map and start the resource in server.cfg with start live_map.
  • Set the bridge and secret in server.cfg (do not commit secrets): 
    set live_map_bridge "http://1.2.3.4:8080/update"
set live_map_secret "your-strong-secret"
  • Deploy the Node bridge on a server reachable by the FiveM host. Set environment LIVE_MAP_SECRET and run node index.js.
  • Host web/index.html on any static host and replace ws://YOUR_BRIDGE_HOST:8080 with your bridge address.

Security, validation and best practices

  • Keep the secret only in server.cfg or an environment variable. Never embed it in client.lua or front-end code.
  • Validate coordinates and rate limits on the server. The example drops values with abs > 100000 and prunes stale entries.
  • Use HTTPS/WSS and firewall rules for production. Require authentication or IP allowlist on the bridge if the map is not public.
  • If you integrate with QBCore/ESX, fetch additional server-side metadata (job, steam) from the framework server API; avoid trusting anything from the client.

Troubleshooting & next steps

  • If you see no markers: check that server sends POSTs (enable server logs) and the bridge returns 200. Use the bridge /snapshot to verify the last payload.
  • For scale: switch to binary protocols (msgpack) or shard by server instance. Use monitoring and analytics for throughput.

Follow the verification workflow: test locally first, validate secrets and logs, and deploy with TLS for public maps. This pattern keeps authority on your FiveM server, prevents spoofing, and is compatible with QBCore/ESX ecosystems when you need framework metadata.
