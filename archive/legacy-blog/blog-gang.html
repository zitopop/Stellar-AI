QBCore Gang System — Architect, Build, Secure

Updated September 2026 · 8 min read · Stellar AI

This guide shows how to plan and implement a compact, secure gang system for QBCore-based FiveM servers. It focuses on server-authoritative flows, validation, and useful integration points (qb-target, stash, shared funds). Included: full destination-labelled files, SQL schema, and a practical installation checklist.

Overview and implementation plan

Goal: add persistent gangs with membership, a shared bank, a stash, and territorial interaction points. Keep all authoritative state on the server, validate every client request, and expose minimal surface to the client (UI triggers and qb-target zones).

Short implementation plan:

  1. Define database schema for gangs and members.
  2. Create a QBCore resource with server and client files, and a small config.
  3. Implement server callbacks/events for create/join/leave/transfer/deposit/withdraw.
  4. Client: qb-target zones for stash and gang menu; basic menus use QBCore UI calls or exports.
  5. Test authoritative flows, exploit cases, and Data validation.

Assumptions and dependencies

  • Server runs QBCore and has one MySQL wrapper installed (oxmysql recommended).
  • qb-target is available for spatial interactions.
  • UI is minimal; you may plug in ox_lib or custom NUI for rich menus.

server/main.lua

local QBCore = exports['qb-core']:GetCoreObject()

-- Simple MySQL helper; assumes oxmysql
local function query(sql, params)
  return exports.oxmysql:fetchSync(sql, params)
end

-- Create tables (run once manually in SQL, below SQL provided in the guide)

QBCore.Functions.CreateCallback('qb-gangs:getPlayerGang', function(source, cb)
  local src = source
  local xPlayer = QBCore.Functions.GetPlayer(src)
  if not xPlayer then cb(nil) return end
  local identifier = xPlayer.PlayerData.citizenid
  local res = query('SELECT g.* FROM gangs g JOIN gang_members m ON g.id = m.gang_id WHERE m.citizenid = ?', {identifier})
  cb(res[1])
end)

RegisterNetEvent('qb-gangs:server:createGang', function(gangName)
  local src = source
  local xPlayer = QBCore.Functions.GetPlayer(src)
  if not xPlayer or type(gangName) ~= 'string' then return end
  -- basic validation
  if #gangName < 3 or #gangName > 24 then
    TriggerClientEvent('QBCore:Notify', src, 'Gang name invalid', 'error')
    return
  end
  -- ensure name unique
  local exists = query('SELECT id FROM gangs WHERE name = ? LIMIT 1', {gangName})
  if exists[1] then
    TriggerClientEvent('QBCore:Notify', src, 'Gang name taken', 'error')
    return
  end
  -- create gang
  local res = exports.oxmysql:insertSync('INSERT INTO gangs (name, fund) VALUES (?, ?)', {gangName, Config.DefaultGangFund})
  if res then
    local gangId = res
    exports.oxmysql:execute('INSERT INTO gang_members (gang_id, citizenid, rank) VALUES (?, ?, ?)', {gangId, xPlayer.PlayerData.citizenid, 'leader'})
    TriggerClientEvent('QBCore:Notify', src, 'Gang created', 'success')
  end
end)

RegisterNetEvent('qb-gangs:server:deposit', function(amount)
  local src = source
  local xPlayer = QBCore.Functions.GetPlayer(src)
  if not xPlayer or type(amount) ~= 'number' or amount <= 0 then return end
  -- ensure player in gang
  local gang = query('SELECT g.* FROM gangs g JOIN gang_members m ON g.id = m.gang_id WHERE m.citizenid = ?', {xPlayer.PlayerData.citizenid})
  if not gang[1] then
    TriggerClientEvent('QBCore:Notify', src, 'You are not in a gang', 'error')
    return
  end
  if xPlayer.Functions.RemoveMoney('bank', amount) then
    exports.oxmysql:execute('UPDATE gangs SET fund = fund + ? WHERE id = ?', {amount, gang[1].id})
    TriggerClientEvent('QBCore:Notify', src, 'Deposited $' .. amount, 'success')
  else
    TriggerClientEvent('QBCore:Notify', src, 'Not enough money', 'error')
  end
end)

        event = 'qb-gangs:client:openStash'
      }
    },
    distance = 2.5
  })

RegisterNetEvent('qb-gangs:client:openStash', function()
  QBCore.Functions.TriggerCallback('qb-gangs:getPlayerGang', function(gang)
    if not gang then
      QBCore.Functions.Notify('You are not in a gang', 'error')
      return
    end
    -- open stash inventory, this is intentionally a placeholder
    -- integrate with your inventory resource (ox_inventory, qb-inventory, etc.)
    QBCore.Functions.Notify('Opening stash for ' .. gang.name)
  end)
end)

SQL schema (run once)

CREATE TABLE IF NOT EXISTS gangs (
  id INT AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(64) UNIQUE NOT NULL,
  fund BIGINT DEFAULT 0
);

CREATE TABLE IF NOT EXISTS gang_members (
  id INT AUTO_INCREMENT PRIMARY KEY,
  gang_id INT NOT NULL,
  citizenid VARCHAR(32) NOT NULL,
  rank VARCHAR(32) DEFAULT 'member',
  FOREIGN KEY (gang_id) REFERENCES gangs(id) ON DELETE CASCADE
);

Security and validation checklist

Every client-originating action must be verified on the server. Use these rules as a minimum:

Check Why
Server-side money/item checks Prevent clients from faking removal/addition of money/items
Membership & rank validation Only leaders should change ranks or remove members
Input sanitisation Reject invalid strings and sizes to avoid DB issues
Rate limiting for expensive ops Prevent spam (e.g., repeated create requests)

Installation & testing steps

  1. Place qb-gangs resource in your resources folder and start it from server.cfg (ensure qb-core loads first).
  2. Run the SQL schema once to create the tables.
  3. Test flows: create gang, join, deposit, open stash. Use server console logs and QBCore notifications to observe results.
  4. Attempt exploit tests: client-sent deposit with negative amounts, fake join — server must reject.
