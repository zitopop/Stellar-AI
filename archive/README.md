# Repository archive

This directory stores non-runtime historical material so the repository root stays focused on deployable product files.

## Archive policy

Place old versions, backups, audit exports, temporary browser scripts, launch research, superseded planning documents, and test-only reference pages here. Do not move files that are required by the deployed site, including public pages, PWA assets, shared runtime CSS/JavaScript, sitemap/robots files, package manifests, or API dependencies.

Archived files are not part of the public website unless a test or historical workflow explicitly reads them. New cleanup work should prefer a dated or descriptive subfolder rather than creating another root-level report.

## Root policy

The root should contain the deployable application shell, public pages and SEO/PWA assets, `README.md`, package manifests, and the approved runtime folders: `api/`, `blog/`, `scripts/`, `tests/`, and `lib/`. Historical and temporary material belongs here under `/archive/`, not beside the production entry points.
